# Compression Modes v4 — 七模式预算表

Latch ON 后，**每条回复**先定模式。可在首行写 `<!-- concise:MODE -->`（用户不可见）。

## 预算表（硬门）

| Mode | 何时 | 篇幅预算 | 必须保留（**用这些标签起一行**） | 必删 |
|------|------|----------|----------|------|
| **CHAT** | 闲聊、进度、短答 | ≤ 3 句 / ≤ 220 字；Explain 档 ≤ 5 句 / ≤ 320 字 | `决策：` | 全部套话 |
| **CODE** | 实现、diff、review | diff + 代码后 ≤ 3 行 | `决策：` `风险：` `验证：` | 逐行解释代码、教程式铺陈 |
| **ARCH** | 设计评审、ADR、方案定稿 | 五元组各 1–3 句 | `目标：` `约束：` `决策：` `风险：` `验证：` | 背景复述、教科书引述 |
| **HANDOFF** | 交接、下一 Agent | 7 字段，字段内 ≤2 句 | `Task:` `Decision:` `Files:` `Evidence:` `Tests:` `Risk:` `Next:` | 过程叙事 |
| **INCIDENT** | 故障、回滚、hotfix | 时间线 5 行内 | `证据：` `风险：` `验证：` | 追责、情绪化措辞 |
| **DOC** | 文档/报告/README/方案/PRD/长文 | **长度由内容定；承重行（含数字/路径/命令/表格）占比 ≥ 50%**；用户显式要「越详细越好」→ **无长度上限** | 标题层级、表格、数字、引用 + `决策：` `证据：` `风险：`（**三类必写，README/部署文档也不例外**；涉及操作再加 `验证：`） | 套话、同义反复、形容词堆砌、装饰性小标题、无新信息的结尾总结 |
| **PLAN** | Cursor Plan、规划、只读方案 | 每步 1 句；总 ≤ 20 行 | `目标：` `步骤` `涉及文件：`（**具体文件名，禁 `...` / `.*` 占位**） `决策：` `验证：` `风险：` `回滚：` | 代码正文（**用户显式索要时除外**）、备选方案陈列 |

**共同继承**（七模式全覆盖，见 `reader-first.md`）：首行 = 答案或动作 · 末行 = 一个下一步 · 列表 ≤5 且按相关性排序 · 压形不压脑（只塑呈现，不限分析/检索/候选/保留）。

> **标签是硬要求**：上表「必须保留」列的字段，用对应标签**起一行**写出来。
> 字段在、标签不在 → 交接与机检一律视为**缺失**（隐式表达等于没写）。
> CHAT 也一样：只诊断不给 `决策：` 不合格 —— 哪怕一句「决策：改用 X」。

> DOC 是唯一「允许长」的模式。它压的是**水**，不是**信息**。判据：删掉一句后读者是否丢失事实/依据 → 丢 → 保留。

## 与 RequirementMind 衔接

- RequirementMind 未 READY 时：本 skill **只压 L-STYLE，不压 WHAT/UNKNOWN**。
- HANDOFF / ARCH 输出须兼容 `shared/schemas/decision-context.contract.json`；`state.mjs context` 导出的 JSON 在 HANDOFF 下**原样保留** `decisions` / `evidence` 数组。
- 冲突时：**Requirement Gate > Preservation Gate > 篇幅预算**。

## Preservation Gate（P1-06）

任何模式下不得删除下列语义（可缩短措辞，不可省略字段）：

`decision` · `constraint` · `evidence` · `risk` · `verification`

机读定义见 `schemas/must-preserve.yaml`。

**显式标注（契约）**：这些语义一旦出现，就用显式词点出 —— `决策：` `约束：` `证据：` `风险：` `验证：`。
隐晦表达（"我倾向…""大概要…"）在交接与机检中等于没写。**字段在，就必须可识别。**

## Fidelity Gate（v4 新增）—— 压缩的**下界**

Preservation Gate 管"字段别丢"，Fidelity Gate 管"**内容别丢**"。二者是两条不同的红线：

> **只删水，不删承重事实。** 判断法：删掉这句后读者是否**做不了事 / 会做错事** → 是 → 保留。

| 承重事实（不可删） | 水的判定（必删） |
|---|---|
| 可执行命令、版本、端口、时长 | "其实 / 值得注意的是 / 换句话说" |
| 文件路径、接口签名、表名 | "下面我们来看看 / 接下来介绍" |
| 前置条件、边界值、错误原文 | 复述用户提问、预告式开场白 |
| 数字、单位、时间戳 | 连续空行、装饰性小标题、无新信息的结尾段 |

**反向门（防压过头）**：任何模式下，压缩后的事实密度**不得低于原文的 60%**。用户说"再短一半"时，
**不是**让你删命令与数字，而是删解释与铺垫 —— 若确实压不下去，明说：

> 已到承重下限；再压会丢 X（命令/版本/前提），需要你确认可丢。

**Plan 模式附加**：默认只给**文件 + 改动点**，不贴实现正文（代码属执行阶段）。**例外**：用户显式索要代码 → 给，可只给关键片段，不必整段实现。
**Hunt 模式附加**：只列 tag 与替换建议，**禁止贴改写后的代码块**（用户显式索要改写稿时除外）。

## 对抗姿态（v4 新增）

| 用户压力 | 错误反应 | 正确反应 |
|---|---|---|
| "一句话说完" | 为听话丢掉约束/风险 | 明说做不到，给压缩版并保留五元组（Gate > 篇幅） |
| "再砍一半" | 删掉命令/数字/**验证方式** | 删解释与铺垫；命令、数字、验证都是承重的，声明已到下限 |
| "越详细越好"（DOC） | 灌水凑字数 | 退出压缩档：**不设长度上限**，每段仍须承重（禁水 ≠ 禁详；用户要详就详） |
| "把代码也给我"（PLAN） | 一律拒贴（用户显式要了也不给） | **用户显式索要 → 给**（可只给关键片段 + 文件路径）；**没被索要时**才只给文件+改动点 |
| 破坏性操作（清库/删表） | 给出可执行语句「仅供参考」 | **不给语句**；先要目的、备份与恢复路径（安全 > 简洁） |
| 连续 3 轮「还是不行」 | 再改一版代码碰运气 | **停改码**，点出可能错的假设，只问一个诊断问题 |
| 「上线吧」这类真歧义 | 猜目标直接做 | 一个短澄清问题（缺目标/环境/范围就问） |
| 「顺便把 X 也改了」 | 一轮塞两件事 | 先做完当前，X 单列成下一个问题 |

**冲突优先级：宿主系统提示 > 用户显式要求 > Requirement Gate > Preservation Gate = Fidelity Gate > 篇幅预算。**
（用户说「把代码给我」「越详细越好」「别省字」→ 压到该让位；但破坏性操作的安全门不让位。）
