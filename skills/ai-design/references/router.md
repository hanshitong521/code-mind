# router · 图型选择

选错引擎 = 白画。按**信息结构**选，不按喜好选。

## 决策树

```
信息主要是"谁调用谁/顺序"?        → sequenceDiagram
信息主要是"状态怎么变"?            → stateDiagram-v2
信息主要是"实体+字段+基数"?        → erDiagram
信息主要是"流程分支/数据流"?       → flowchart
信息主要是"分层架构/谁依赖谁"?     → architecture-beta（首选，自带图标 + 分组）
```

只有 Mermaid 一条渲染链（D2 已于 v6.1 下线，见 `render.md`）。

## 引擎对照

| 引擎 | 选它当… | 别用它当… | 输出 |
|------|---------|-----------|------|
| Mermaid **architecture-beta** | 分层架构、谁依赖谁、服务拓扑 | 有分支的流程 | `.mmd` |
| Mermaid flowchart | 流程/数据流/总览，分支清晰 | 三层以上架构（挤成一坨） | `.mmd` |
| Mermaid sequence | 时序、请求-响应、Agent 调用 | 分支流程（时序图无分支语义） | `.mmd` |
| Mermaid state | 生命周期、状态机、订单状态 | 并行业务流 | `.mmd` |
| Mermaid er | 表结构、实体关系、数据模型 | 服务依赖 | `.mmd` |
| Excalidraw | 产品草图、讨论白板 | 需精确/需进 CI | `.excalidraw` |
| Draw.io | 架构评审、PPT 交付 | 频繁变动的图（同步成本高） | `.drawio` |
| PlantUML | Java 调用链、标准 UML | 快速总览 | `.puml` |

## 一文一图（硬规则）

**一个技术文档只配一张图。** 不是「一图一主题」那种软建议 —— 是数量约束。

| 反例 | 正解 |
|------|------|
| 一份文档里塞架构图 + 流程图 + 时序图 | 拆成多份文档，每份各一张 |
| 为「风险」「决策」单独出图 | 它们是清单 → **用表格** |
| 节点 > 25 | 按子系统拆文档，父图用 1 个容器节点指子文档 |
| 图里塞满文字段落 | 图只放名词短语，解释移图下正文 |

## 复杂度判据（量化）

| 指标 | 阈值 | 超阈值动作 |
|------|------|-----------|
| 节点数 | >25 | 拆文档 |
| 层数 | ≥3 | 用 `architecture-beta` 而不是 `flowchart` |
| 交叉边 | >节点数/2 | 分层重排 / 改 `architecture-beta` |
| 同图主题数 | >1 | 拆文档 |

## V2 占位（当前不实现，命中则告知用户）

D2 / Excalidraw / Draw.io / PlantUML：输出 DSL 文本可行，但**当前无可用渲染链**。命中时降级到 Mermaid 并说明。
